# 85 — 删掉「改动点」：一个从未产出过的功能

用户 2026-09-27 看到"它到现在在线上没渲染出过一个像素"之后说：**「那就先删了」**。

这一刀删的不是"暂时没用的东西"，而是**从来没有产出过的东西** —— 判据是 #82 立的那条：
先量，再决定；两种结果都值钱。量出来的结果是负的，于是删。

## 一、判据（都不是推理，是实测）

| 事实 | 数字 | 出处 |
| --- | --- | --- |
| 全站 `changes` 非空的条目 | **0 条** | #82 第二节（生产只读） |
| 47 条修正案里 `changeMarkers` 非 null | **0 条** | 同上 |
| "体裁=修正案 且 证据=附件正文"的候选 | 恰好 5 条（全部 open、都有可读正文附件） | 同上 |
| 这 5 条点名重跑（5 次境外调用）之后 | `changes` 仍是 **0 条**、`changeMarkers` 仍是 null | #82 第六节 / #81 执行记录 |
| 全库有「对照表」附件的条目 | **0 条**（唯一有强证据的那条没有摘要） | #79 第一节 |

也就是说：**这一刀在它最该服务的体裁上、在真的喂进正文的前提下、在模型有充分理由吐改动点的
情况下，一次都没有产出。** 留着它的代价不是磁盘，而是每个读代码的人都要重新问一遍
"它为什么不出现"，以及每个渲染路径上挂着一个永不成立的分支。

同时删掉的还有它带来的一整套：提示词里那段（含"本页会另给一行覆盖度"的承诺）、
模型输出字段、逐字反查、覆盖度分母与那三句话、**体裁门控**、详情页整块表格、
stub 的回响逻辑、以及**只为计数而存在的那份词表**（`CHANGE_TEXT_MARKERS`）。

## 二、刻意留着的两样（以及为什么它们与改动点不同）

1. **体裁（`notice-genre.ts`）**：它有自己的读者面 —— 详情页的体裁角标，以及
   "修正案 / 新案用不同模板"这条判断依据。改动点只是它的**一个消费者**，不是它存在的理由。
2. **编制说明要点（`explanationPoints`）**：它在生产上**真的渲染出来过**（金丝雀从"整节不渲染"
   变成 2 条，见 #81）。删功能的标准是"有没有产出过"，不是"它属于哪一批" —— 同一个 #76 里
   这两刀一个留一个删，差别就在这里。

顺带一处**改名**：`src/lib/amendment-coverage.ts` → `src/lib/explanation-coverage.ts`。
改动点那一半删掉后，这个文件只剩编制说明的覆盖度，而名字还叫"修正案覆盖度"——
留着一个不再管修正案的名字，就是下一个读代码的人的第一个坑。

## 三、删一个功能时真正要处理的东西（这一刀学到的清单）

只删写入侧是不够的，**库里的数据还在**。这次涉及七处，漏任何一处都不报错：

1. 模型输出字段（`ports.ts` 的 `changes`）；
2. 提示词里的字段说明与那几条规则（`openai-compatible-llm.ts`）；
3. 归一化与逐字反查（`buildChanges`）；
4. 覆盖度计数与那三句文案；
5. 体裁门控（它门控的对象没了）；
6. 渲染（详情页那一整块 + `hasAttachmentPoints` 的第三个条件）；
7. **读侧** —— 生产库里那批摘要**还带着 `changes` / `changeMarkers` 两个键**。

第 7 条最容易漏，而且漏了的表现正是本仓库最怕的那种：解析报形状异常 ⇒ 存量条目从
「有摘要」掉回「待人工复核」占位，而没有任何东西会提醒你。所以：

- 单元测试钉在读侧（`summary-shape.test.mjs`：**旧行带着已删除的键也要照常解析**，
  且解析结果里不该出现这两个字段）；
- e2e 钉在**页面**上（`notice-genre-badge.test.mjs`：手工把两个键写回库再取详情页，
  断言摘要卡照常渲染、而「改动点」那一节一个字都不出现）。
  这条刻意用**注入**的方式造出旧行 —— 新摘要是不会再产生这两个键的，
  不注入的话它测的就是一条不存在的路径（本仓库反复栽过的那种假绿灯）。

运维侧同样要收口：`deploy/audit-genre-rebucket.sql` 第 ⑤ 段原来有两列问"改动点非空 / 带过覆盖度键"，
功能删掉后它们**永远读出 0**，留着只会误导下一个读报表的人 —— 已删掉那两列。

## 四、门

| 项 | 前 | 后 |

| 单测 | 524 | **514**（删掉 11 条改动点用例，新增 3 条：旧键兼容、词表只有一份、说明覆盖度"列得少要照实说少"） |
| e2e | 386 | **384**（删掉 2 条改动点用例；另 2 条原地改写成只测体裁与前提，"旧的空栏"那条改写成"注入旧键也不复活"） |
| pin | 133 | **131**（删掉 5 条改动点的、新增 3 条说明覆盖度的 —— 判据同构，搬过去而不是连带删掉） |

一条刻意的选择：覆盖度那几条 pin **没有跟着功能一起删**，而是搬到编制说明那一侧
（"列得少要照实说少"这个判据两边同构）。删功能时顺手把**同构的判据**也删掉，
下一轮就会以为那类错误已经被覆盖过了。

**搬运过程中又抓到一次假绿灯**（本轮第二次，与 #84 那次同源）：第一条搬过去的 pin 把
`pattern` 指到了"分母为 0 时不写全部"那条用例上，而它测的是**另一个分支**（`sections === 0`）——
撤掉 `listed >= sections` 那行它照样绿，脚本当场报「这条断言没钉住任何东西」。
修法不是改 pin 的靶点，而是**补上缺的那条用例**（"列得比数到的少要照实说少"）：
原来那条判据是随改动点的测试一起被删掉的，编制说明这一侧本来就没有人测过它。

## 六、证据边界
