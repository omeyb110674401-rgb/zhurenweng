# 79 — 体裁词表与改动词表不一致：44% 的「修正案」会渲染出一个空的「改动点」栏

2026-09-25 在执行 A3（#76 线上取证）时从生产实测中查出，**不是**推理出来的。

## 一、现象

金丝雀 `90311b62a3bfa88b`（生态环境部《美丽河湖评价技术导则（征求意见稿）》）
重跑摘要后，线上详情页出现：

```html
<div class="summary-section" data-testid="summary-changes">
  <h2 class="summary-section-title">改动点</h2>
  <p class="summary-section-note" data-testid="summary-change-coverage">
    未在附件正文里检测到成文的修改表述（按标题判为修正案）
  </p>
</div>
```

即读者看到**一个标题叫「改动点」、里面却说"没检测到改动"的空栏**。同一条的库里数据：

```
changes = 0 条    explanationPoints = 0 条    amendmentCoverage = NULL
changeMarkers = {"total": 0, "byKind": {"add":0,"delete":0,"modify":0,"renumber":0}}
genre = amendment, genre_evidence = attachment_text,
genre_basis = 附件正文含对照措辞「现行」
```

而它实际是一份**全新标准**的征求意见稿 —— 根本没有"改了哪几处"这回事。

## 二、根因：两份词表并不一致，而注释声称它们一致

`notice-genre.ts:56-58`：

> 导出给 `amendment-coverage.ts` 用同一份词表 —— 判体裁和算覆盖度必须认同一批词，
> 否则会出现"判成修正案但覆盖度算出 0 处改动"这种自相矛盾的页面。

`amendment-coverage.ts:26-27`：`刻意只认"官方写法"……一套词表两个用途`。

**两处声明都不成立。** 实际是两份不同的表：

| | 词 |
| --- | --- |
| 体裁 `AMENDMENT_TEXT_MARKERS`（`notice-genre.ts:60`） | `修改为` / `删去` / `增加一条` / **`原条款`** / **`现行`** |
| 改动 `KIND_PATTERNS`（`amendment-coverage.ts:29-34`） | `修改为` / `修改如下` / `作…修改` / `增加一条` / `新增…条` / `删去` / `删除` / `作为第…条` / `顺序作…调整` |

**`现行` 与 `原条款` 只在前者里。** 正文里只要出现这两个词之一、而没有出现任何一个改动词，
就是 `genre=amendment` + `changeMarkers.total=0` —— 上面那个自相矛盾的页面。

`现行` 尤其糟：**全新标准的编制说明里本来就会说"现行标准"**，所以它是把新案误判成修正案的
高频来源。`notice-genre.ts:52` 那句判断「普通新案草案不会出现」在生产的 22 条实例面前不成立。

## 三、受影响面（生产实测）

```
判成修正案总数 52
  标题含「修正/修订」（标题证据）                 24
  附件正文含对照措辞「现行」                    22   ← 误判来源
  附件正文含对照措辞「修改为」                   4   ← 真修正案
  附件「《中华人民共和国职业教育法修订对照表》」是新旧对照表   1   ← 最强证据
  附件正文含对照措辞「原条款」                   1   ← 同类问题
```

- **23 / 52（44%）** 靠 `现行`/`原条款` 判进来，重跑摘要后各自会长出一个空的「改动点」栏。
- 全库目前只有 1 条摘要有 `changeMarkers`（就是刚重跑的金丝雀），且它 `total=0`
  —— 所以这个栏位**今天只有个例可见，但会随摘要逐条重跑而扩散**。
- 那条**唯一有强证据**（附件是《…修订对照表》）的条目**没有摘要**，
  也就是说：**现在库里不存在任何一条能渲染出非空改动点的条目**。
  全库有「对照表」附件的条目数 = **0**（`attachment_names` 判据只命中那 1 条，且无摘要）。

## 四、为什么它一直没被测出来

那条不变式**只写在注释里，没有任何测试钉它**。相关测试只覆盖了单份词表的行为：

- `tests/unit/amendment-changes.test.mjs:99` 用一句人造文本 `'一份没有修改表述的正文'`
  验 `no_markers` 分支 —— 覆盖了"空"这个状态，但**没覆盖"体裁是怎么走到这个状态的"**；
- `tests/e2e/summary-amendment-changes.test.mjs:235` 用的 `AMENDED_TEXT` 里本来就含改动词。

所以两份词表各自被钉住了，**它们之间的关系没人钉**，于是静默漂移。
要补的门很明确：一条单测断言 `AMENDMENT_TEXT_MARKERS` 的每个词都至少被
`KIND_PATTERNS` 里某条正则命中（或显式声明某个词是"只判体裁、不计数"的例外）。

## 五、两处顺带的文案错

1. `amendment-coverage.ts:73` 的文案硬编码成「（按标题判为修正案）」，
   而这 22 条的判据是**附件正文**。读者据此会以为"是按标题猜的"，与事实不符。
2. `amendment-coverage.ts:68` 的注释写「体裁是靠标题判的」——这个前提在 #76 加入
   `attachment_text` / `attachment_names` 两级证据之后就已经过期。

## 六、建议改法（**未执行** —— 超出本批授权，且要一次判断）

方向有三条，取舍不同，不该由我单方面定：

1. **收窄体裁词表**：把 `现行`（可能还有 `原条款`）从 `AMENDMENT_TEXT_MARKERS` 里去掉。
   最贴近"它本来就不该是修正案信号"这个事实，但**要重判那 23 条的体裁**（重跑体裁推导），
   且会改变它们的摘要形态。
2. **让词表真正一致**：把 `现行`/`原条款` 加进 `KIND_PATTERNS`。不变式立刻成立，
   但「现行标准」会被数成"1 处改动"——计数是错的，等于用一个错数换一个空栏。
3. **只修展示**：`no_markers` 时**整个「改动点」小节不渲染**（与 `explanationPoints` 为空时
   不渲染「编制说明要点」一致），并把文案改成与判据相符。改动面最小、立即消除读者可见的矛盾，
   但不解决体裁误判本身。

我倾向 **1 + 3**：3 立刻消除读者看到的矛盾，1 才是根治；2 不建议。
无论选哪条，都应同时补上第四节那条钉住两份词表关系的门。

## 七、另一个未定的问题：`explanationPoints` 为什么是 0

同一条金丝雀的编制说明**确实喂进去了**：

```
3.《美丽河湖评价技术导则（征求意见稿）》编制说明   status=ok  char_count=17631  fed_to_summary=1
2.美丽河湖评价技术导则（征求意见稿）              status=ok  char_count=7132   fed_to_summary=1
1.征求意见单位名单                              status=no_draft_text  char_count=236  fed_to_summary=0
```

`explanationSections = 39`（说明里检出 39 个小节标题），上限也不卡
（`MAX_EXPLANATION_POINTS = 24`，说明侧预算 `MAX_EXPLANATION_TOTAL_CHARS = 10_000`），
**但落库的 `explanationPoints` 是 0 条**，页面因此完全不渲染「编制说明要点」小节。

两种可能，从库里区分不了：

- 模型自己返回了空数组（提示词第 7 条要求"说明里没有分层小标题时输出空数组，不要自己造小节名"，
  模型可能判定这些标题不算分层小标题）；
- 模型返回了内容，但 `quote` 没通过 `buildQuotedSummary` 的**逐字反查**，被整条丢弃。

**定位方法**：拿一次模型原始输出来看（而不是继续从落库结果反推）。这是下一个动作，
在没看到原始输出之前不应下任何结论。
