# 版本对比在单侧缺正文时把上一版整篇报成「删除」

## 审计结论（2026-09-21，issue #41 记录待办后本轮修复）

| 检查项 | 结论 |
| --- | --- |
| 单侧缺正文的对比渲染 | **缺陷**（见下） |
| 对比页 metadata | **缺陷** —— 整页共用 layout 的通用标题（每个条目的对比页标题一模一样）、无 robots 声明 |
| 无上一版的条目 | 无缺陷 —— 友好空态 + 返回详情页入口 |
| 不存在 / 非法 id | 无缺陷 —— 404（含路径穿越尝试） |

## 缺陷：把「没抓到正文」渲染成「上一版被整篇删除」

`diffNoticeBodies(上一版正文, null)` 会把上一版每个条款都输出成 `removed` —— 对比页
于是整篇显示「删除」，读者以为这一轮把草案全删了。真相是**我们这轮没抓到正文**：同一
时刻详情页显示的是「正文未取到」。反向（上一版缺正文）则整篇「新增」。

原有的空态只在**两侧都空**时才出现（`rows.length === 0`），所以这种谎报此前完全静默 ——
页面既没有「删除」以外的解释，也没有任何「数据不全」的提示。这类「数据缺口被渲染成
内容主张」的缺陷在本项目已出现过三次（issue #24 静默丢日期、#30 降级覆盖已入库正文、
本次），共同点是：**页面把「我们不知道」表达成了「我们知道它没有」**。

可达性说明：生产库 `version_of` 全空（issue #35 审计：收录窗口内没有同案多轮公示），
对比页当前只能渲染空态 —— 所以这是**潜伏**缺陷（issue #41 因此把它记录待办而不是
抢着改）。但版本链一旦出现第一个多轮条目就会立刻暴露，且那时没有测试兜底。

## 修复

1. **可比性判定（`src/lib/notice-diff.ts`）**：新增 `diffComparability(oldBody, newBody)`
   → `comparable` / `missing-old` / `missing-new` / `missing-both`，口径与切分函数一致
   （`splitClauses` 切不出条款就算没有正文：空串、纯空白、null 一律算缺）；
2. **函数守卫**：`diffNoticeBodies` 在不可比时**返回空数组** —— 宁可什么都不输出，
   也不产生「整篇删除 / 整篇新增」。这样即使将来有别的调用方忘了判可比性，最坏也只是
   少显示，不会说谎；
3. **页面两态文案**（`/notices/[id]/diff`）：按可比性渲染 ——
   - 本轮缺正文 → 「本轮（第 N 轮）的正文未取到，无法对比……上一轮正文可在[上一轮条目页]查看」；
   - 上一轮缺正文 → 「上一轮的正文未取到，无法对比……本轮正文见[本轮条目页]与下方官方原文」；
   - 两侧都缺 → 保留原「两轮都无可比对正文」说明；可比 → 照常三态对比；
4. **该页 metadata**：`title: 条款对比：<条目标题> —— 主人翁` +
   `robots: { index: false, follow: true }`（对比页正文是两版条目正文的并集，与两个
   条目页高度重复 → 不收录，但 follow 保留链接发现）。**刻意不写 `alternates`**：
   一旦导出该字段就会整块覆盖 layout 的 RSS 自动发现 —— issue #41 刚在首页踩过这个坑。

## 验收

- 单元（131，新增 7）：`tests/unit/notice-diff.test.mjs` —— 可比性四态（含 `''` / 纯空白 /
  `null` / `undefined`）、判定与 `splitClauses` 口径一致、守卫在单侧缺正文时返回空数组、
  **可比时照常产出差异行**（防守卫误伤）；
- E2E（177，新增 6）：新增 fixture 集 `fixtures/e2e-versions-degraded`（两条版本链各三轮：
  湿地 r3 本轮无正文、草原 r1 上一轮无正文，其余可比；另含一条单轮条目守住空态），
  断言：本轮缺 → 有 `diff-incomplete-body`、有上一轮入口、**无任何差异行**（尤其无
  `diff-removed`）；上一轮缺 → 同理且无 `diff-added`；可比链条 → 三态齐全（含行内
  新增片段）；单轮条目 → 仍是空态；对比页 metadata 三条（标题含条目名、noindex + follow、
  RSS 自动发现仍在）；
- **红检**：① 去掉守卫 → 单元 2 项变红；② 再去掉页面的可比性分支（退回「有行就渲染」
  的旧决策）→ e2e 2 项变红（正是「本轮缺正文」「上一轮缺正文」两条），恢复后全绿；
- 本地全量：单元 131 + E2E 177 全绿，typecheck / lint 干净；
- 线上核验（部署后）：对比页 200 且**标题已是个性化的**（`条款对比：住房城乡建设部办公厅
  关于国家标准《混凝土质量控制标准（修订征求意见稿）》…`，不再是 layout 的通用标题）、
  `noindex, follow`、无 canonical 但 **RSS 自动发现仍在**、无版本链的条目仍是空态、
  非法 id 404、首页 / 统计页 / feed / sitemap 全部 200；
- **缺正文两态无法线上核验**（生产没有任何版本链）—— 因此在容器里直接跑部署后的源码
  核对守卫：`本轮缺 → missing-new 差异行数 0`、`上轮缺 → missing-old 差异行数 0`、
  `双侧有 → comparable 差异行数 1`。页面接线由 e2e 的 fixture 覆盖（那正是本 issue 的
  数据形态）。

## 未做（有意）

- **不把缺正文的轮次从版本链里摘掉**：链关系（同一法案的第 N 轮）是真的，缺的只是正文；
  摘链会把「有这一轮」这个事实也一起丢掉；
- **不给对比页加 canonical**：noindex 页不需要自指 canonical，而写 `alternates` 会覆盖
  layout 的 RSS 自动发现（见上）；
- **不动 issue #41 已上线的首页索引口径**：本轮只碰对比页。
