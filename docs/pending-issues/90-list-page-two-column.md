# 90 列表页 / 首页宽屏两栏（筛选入 rail）

> 用户 2026-10-02 拍板变体 A。它是 #88 两刀做完后剩下的四件之一（清单见 `88-detail-page-layout.md` §6）。

## 一、先量再改

用 `scripts/measure-rendered-geometry.mjs` 对着**线上首页**量（改动前）：

| 指标（1440×900） | 读数 |
| --- | --- |
| 容器宽 | **760**（左右各空 333px） |
| 第一条卡 `top` | 659 |
| 卡高 | 163 |
| **整屏能读完的条数** | **1** |
| 375×800 | 第一条 `top` 936 ⇒ 首屏 **0 条** |

筛选块（排序档 / 范围 / 受众面 / 领域 / 关键词 / 机关 / 来源 / 筛选按钮）占掉整个首屏 ——
所以"一页的信息量不足"**不只是宽度问题**：宽度是两侧各空 333px，而**真正把列表顶下去的是筛选块**。
只加宽、不挪筛选，首屏还是只能看到一条多。

## 二、拍板与形状

用户选 **A：宽屏两栏、筛选入 rail**。落地形状：

- 断点 **1000px**（与详情页同一个，用户拍板过的那个）；
- rail 放**右**：这一栏装的就是原来压在首屏的那一整块。放右 = 阅读顺序仍是"先看列表、再看筛选"，
  与改动前"筛选在上、列表在下"的先后一致；整页左边缘（站点标题、搜索框、条目卡）对齐不动。
  放左会把内容整体右推，视觉上像换了一个站；
- **DOM 顺序一个字没改**（筛选条仍排在结果区之前）：窄屏的落回因此不需要任何 `order`，
  也不会让键盘 Tab 的到达顺序与眼睛看到的相反；
- 宽度与详情页**同一条连续式**（`min(1120px, max(760px, 100vw − 48px))`，理由与 `100vw`/`100%`
  那个坑见 `88-detail-page-layout.md` §7.10）。

## 三、一个只有渲染才看得见的缺陷（第三例）

第一版靠**栅格自动放置**换位，注释里还写着"筛选条（第一个子项）自然落到第一列、结果区落到第二列"——
**那是反的**：`grid-template-columns: minmax(0,1fr) 320px` 的第一列是主栏，而 DOM 里筛选条排在前面，
于是**筛选条占掉 772px 的主栏、列表被塞进 320px 的右栏**。

这与详情页那一刀的两个缺陷同族（结构看着对、渲染出来是错的），而 e2e 没有浏览器照样看不出来。
修法：宽屏那一档**显式写死列位**（`.list-main` → 第 1 列、`.filter-bar` → 第 2 列）——
方向要的是"列表在左、筛选在右"，与 DOM 顺序相反，自动放置永远做不到。
`tests/e2e/list-layout.test.mjs` 里专门有一条断言钉这件事（撤掉列位就变红）。

## 四、落地读数（本地渲染实测）

| 视口 | 容器宽 | 筛选条 | 列表 | 横向溢出 |
| --- | --- | --- | --- | --- |
| 1440×900 | 1120 | 320 @ x=929（右栏） | 736 @ x=177（主栏） | 无 |
| 1000×900 | 952 | 320 @ x=625 | 568 @ x=41 | 无 |
| 999×900 | 951 | 单栏 911（在列表上方） | 单栏 911 | 无 |
| 375×800 | 360 | 单栏 332 | 单栏 332 | 无 |

**第一条卡的 `top` 从 659 → 376**（上移 283px）—— 筛选块不再占首屏，这是"信息量"变多的主因。
容器宽 999 ⇒ 951、1000 ⇒ 952：断点两侧只差 1px（亚像素），**没有跳变**。

## 六、没做 / 留给下一刀

1. **搜索页（`/search`）这一刀没动**。它没有 rail 内容（控件是页头那个搜索框），
   把容器放宽到 1120 只会得到"页头 1072、结果 760"那种拉出 **312px 空带**的半成品 ——
   那不是"信息量变多"，是"没排完"。要不要跟着改（含"把搜索框搬进 rail"那个做法）需要它自己的一刀。
   注：用户当时选的是"首页/搜索页"，这是 Lead 按上面的理由缩的范围，**不是遗漏**。
2. **rail 没做 sticky**：整块筛选条在 900px 高的屏上可能超过视口，sticky 会让底部几个控件
   永远够不到（详情页右栏敢 sticky 是因为它短）。
3. **1000px 时列表列只有 568px**（比改动前的 760 窄）：断点是用户拍的 1000、与详情页一致；
   要不要给列表页单独一个更高的断点（比如 1100），等真实观感再说 —— 本刀没自作主张。
4. **卡片宽度 736**（改动前 760）：这 24px 的差来自宽屏内边距 20→24。
5. **翻页区与"共 N 条"仍留在 section 直下**（没搬进 `.list-main`）：`pagination.test.mjs` 等
   按 `data-testid="X"[^>]*>([^<]*)<` 取值，搬进去首字符就不是文本了 —— 那是为测试形状服务的，
   不是为版式服务，记在这里免得下一个人"顺手整理"。
