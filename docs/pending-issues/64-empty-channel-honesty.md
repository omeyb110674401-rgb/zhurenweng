# issue #64：取不到提交方式时，页面一片沉默（迭代 5 第 3 刀：诚实化收尾）

对应提交：（第 3 刀）

## 一、这一刀解决什么

issue #26 给渠道抽取定了三条自律，第三条是「取不到就返回空数组，页面不渲染该块 ——
不编一条『通常可通过邮件提出』凑数」。这条自律挡住了**瞎编**，却留下另一种不诚实：

详情页的「意见提交方式」在取不到时整块消失，读者看到的是一片空白。而空白至少可能意味着
四种完全不同的事实：

1. 本站**根本没抓到这一条的正文**（只有公告标题与链接）；
2. 抓到了正文，但正文里没有按常见句式写出的邮箱 / 传真 / 地址 / 在线入口；
3. 渠道写在随文附件里，而附件已被抽出正文 / 附件读不出来 / 抽取还没跑到这一条；
4. 原文确实没写受理方式（这一种我们**无法从数据里区分出来**）。

1、2、3 的行动含义不同（①连原文正文都没有，只能去原文页；②③该在正文末尾与附件里找），
页面却给出同一种沉默。更糟的是分步指引的兜底句写的是「通常可通过在线表单、电子邮件或信函提出」
—— 那是一句没有任何本页依据的猜测，读者会照着找邮箱，而这条可能压根只收信函。

## 二、做了什么

- 新增判定 `src/lib/channel-guidance.ts`（纯函数）：把「为什么这块是空的」收成一个可测的结论。
- `SubmissionChannels` 在空的时候不再留白，而是渲染一个中性外观的说明块：
  说清是哪一种事实、要不要去附件、并给出官方原文页面链接。
- 分步指引第 3 步的兜底句换掉：不再说「通常可通过在线表单、电子邮件或信函提出」，
  改为「到官方原文页面找『反馈方式 / 意见反馈』那一段并按其办理」——
  仍然不猜渠道类型，但给了可执行的动作。
- 外观：空态块用细虚线边框 + 中性灰标题（抽到渠道的那块是绿色标题）。
  同一副外观承载两种相反的事实，等于让颜色撒谎。

**仍然不做的事**：不编任何一条渠道、不改抽取正则的覆盖面、不新增需要维护的列。
判据只用仓库里已有的事实（正文长度、附件抽取报告）。

## 三、几个决定的理由

**「抽取还没跑到这一条」不能报成「没有附件」**。详情页的附件报告有三种来源
（见 #57 第 6 步）：有行、无行且条目本来就没附件、无行但条目挂着附件（抽取还没到）。
第三种如果被读成「这条没有附件」，页面就白删了一个读者本来可以自己去点的东西。
所以 `attachment` 是四值的，`unknown` 时**不提附件**。

**只有附件正文真的被抽出来时，才把读者指向附件**。`read-and-used` 与 `read-not-used`
（影子档：抽到了但没喂给摘要）都算"可读"—— 区别只在于本页有没有替读者读过它，
而"去附件里找受理方式"这个动作两者都成立。`unreadable` 则如实说"没能读出文字，
可能在附件里"，不承诺附件里一定有。

**字数要说出口**（「本站抓到了 4200 字正文，但里面没有…」）。它是"我们确实读过这一页"
的证据；只说"没找到"更像没干活。

**不区分第 4 种事实**。数据里没有任何东西能证明"原文没写受理方式" ——
抽取失败与原文缺失在观测上同形。所以文案停在"本站没取到"，
不说"这条没有写"。这是本刀唯一有意留下的不精确，写在这里而不是藏在措辞里。

## 四、上线后要核对的一个数

本刀的收益取决于**空态占比**，而这个数目前没测过（本地没有生产数据）。
部署后跑一次只读核对：库内 `status='open'` 的条目里，有多少条详情页会落到空态块
（判据与页面同一条：`buildNoticeBrief(...).channels.length === 0` 且摘要无渠道）。

- 若占比很低（<5%）：本刀是收尾 polish，后续不必再投入；
- 若占比高（>30%）：真正的问题在**抽取覆盖面**而不是文案，下一步该动
  `notice-brief.ts` 的句式表（按空态条目的真实写法补规则），而不是继续加说明。
