# 审计：附件链接有效性与发稿时间线（含附件块出路提示）

## 审计方法（脚本落在 `scripts/`，只读、可重跑）

| 脚本 | 做法 | 生产基线（2026-09-21） |
| --- | --- | --- |
| `scripts/audit-attachments.mjs` | 340 个附件引用按 URL 去重后逐个探测（先 HEAD，405/403/501 时退回 Range GET），250ms 礼貌间隔 | **309 个 2xx、31 个 403** |
| `scripts/audit-attachment-shape.mjs` | 名字质量 + 取前 1KB 做魔数校验（是不是网页伪装成附件）+ 重复 URL + 同源引用统计 | 264/340 名字无扩展名（源站 URL 本身无扩展名）、**0 个像网页**、0 重复 |
| `scripts/audit-versions.mjs` | 用生产代码的规范化函数给每条算版本键，报告应链未链的组、脏链、以及用更松的「法案名」键找近似组 | 严格键 177 组全单成员；松键也无任何组有第二个成员 |

## 发现 1：31 个附件链接 403（全部来自工信部）

- 全部指向 `https://jyhwzhq.miit.gov.cn/cms_files/filemanager/...`；
- 该主机**连根路径都 403**，响应体是回显 `client_ip` 的 WAF 拦截页；
- 从**两类独立网络**（阿里云杭州 ECS、开发机）都是 403，换浏览器 UA、加 Referer、
  Range GET 都一样；
- 官方页面（`www.miit.gov.cn/gzcy/yjzj/art/...`）链接的就是**同一批 URL** ——
  不是我们解析错了。

**判断**：无法确认普通用户浏览器是否同样被拦（WAF 可能只拦机房 IP）。因此
**不隐藏、不改写**这些链接 —— 藏掉等于删掉可能可用的入口。

## 发现 2：附件块缺少失败时的出路（本次修复的缺陷）

附件块把每个链接都呈现为同等可靠，而唯一的退路（官方原文）在页面顶部与正文来源行，
离附件列表很远。用户点进一个陌生站点的错误页时，会以为是我们站坏了。

**修复**：附件块内新增一行提示（`data-testid="attachment-fallback"`）：
「附件打不开？部分政府站点对下载有网络或会话限制，可到**官方原文页面**获取。」
链接指向**该条目的官方原文页**（与 `official-url` 同址）。无附件的条目不渲染附件块，
也就没有这行。

## 发现 3：发稿时间线全部自洽（无缺陷）

| --- | --- |
| 发布日期缺失 | 0 |

| 倒计时边界 | 「今天截止」「明天截止」有专门文案与紧急样式（实测当日截止 6 条渲染正常） |
| `version_of` 非空 | 0 条 —— 见下 |

## 发现 4：版本链 0 条不是失效，而是数据实况

`version_of` 全空看起来像「关联逻辑没生效」，实测否：按「标题规范化键 × 机关」分组
177 组**全部单成员**；换成更松的「法案名」（标题里最长的《…》去括号段与标点）分组，
**没有任何组有第二个成员**。即收录窗口（约 9 个月）内确实不存在同一法案的多轮公示。
脏链检查（`version_of` 指向非同组条目）为 0。

## 验收

- e2e 新增 1 条（`tests/e2e/sources-mohurd.test.mjs`）：出路提示存在、文案对、
  链接与页面 `official-url` 同址（不写死生产域名 —— fixture 场景下详情 URL 落在
  本地 fixture 源站）；
- **红色证据**：线上旧代码的两个附件页都测到 `attachment-fallback` 缺失，
  新代码的 e2e 通过（presence 断言对旧代码必然失败）；
- 线上核验：20 附件的生态环境部条目与 3 附件的工信部条目都出现出路提示且指向各自
  官方原文页；无附件的条目两者都没有；
- 本地：单元 103 + E2E 161 全绿，typecheck / lint 干净。

## 未做（有意）

- 不隐藏 / 不改写被拦的工信部附件链接（理由见上）；
- 不在抓取期探测附件可达性：我们的机房 IP 403 不代表用户 403，用它决定「隐藏」
  会误伤；且每轮多出上百个请求，不符合礼貌抓取。
