## 三、要一次判断（有取舍，我不单方面定）

### D. PG 那一半：要么能测、要么明说没测（P1 第 5 条）

实测：**10 个 repo 模块** import `schema/sqlite.ts`（versions / summaries / subscriptions / stats /
sources / reminders / notifications / alerts / notices / attachments），`src/db/client.ts:89` 是
`return db as unknown as AppDatabase;` ⇒ 生产跑的 SQLite→PG 类型转换**从未被执行过**，
而这条路已经出过一次真 bug（迁移静默跳过那次）。

- **最小动作（建议先做这个，一行字的成本）**：把这条边界写进 ADR-0001，让它**不再看起来是绿的**；
- 进一步：给 repo 层加一层双方言类型，或至少给"只在 PG 上成立"的分支加形状守卫
  （先例：`periodDaysExpr` 是唯一被允许分方言的地方，写在 ADR-0001 里）。

### E. 7 个幽灵旋钮逐条定生死（P1 第 6 条）

实测：`LIST_PAGE_SIZE` / `SEARCH_PAGE_SIZE` / `SUMMARY_MAX_RETRIES` / `SUMMARY_RETRY_DELAY_MS` /
`ATTACHMENT_MAX_ATTEMPTS` / `ATTACHMENT_NOTICES_PER_ROUND` / `ATTACHMENT_PROBE_BYTES`
—— `docker-compose.yml` **一个都不转发**（逐条 grep 过，7/7 都不在）。

它们仍有缺省值、仍被文档当成可调项（`README.md` 教人"改后 `docker compose up -d web` 即生效"，
`FOLLOWUPS.md` 教人调重试次数"都是改 `.env`"）⇒ **照文档做但没反应**，是最难查的一类问题。

逐条二选一：**加进 compose**（= 承诺可调，要连带写进 `deploy-env-contract` 的三方一致性断言），
或**把文档里的承诺删掉、旋钮降级成代码常量**。
我最想先定的两个：`LIST_PAGE_SIZE`（决定首页一页几条，读者看得见的那个数）、
`SUMMARY_MAX_RETRIES`（决定一次摘要最坏占多久）。
