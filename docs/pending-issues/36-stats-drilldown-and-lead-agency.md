# 统计页缺钻取入口，且机关口径与筛选不一致

## 审计发现（2026-09-21 线上）

### 1. 统计页的数字全是死胡同

`/stats` 两张表（各部门公示量、公示量月度趋势）里的数字都是纯文本，全页仅有的链接是
点击 Top 榜的条目链接 —— 看到「工业和信息化部 24」想点进去看是哪 24 条，没有路。

### 2. 机关口径不一致：统计 25 / 筛选 26

统计页「各部门公示量」按**牵头机关**归并（`leadAgencyOf`，联合发文只记一次，
所以各部门之和 = 条目总数 178）；首页机关筛选按**任一参与机关**命中
（issue #21 的特性，联合发文选任一方都能筛到）。

逐个核对 16 个机关，15 个一致、**国家发展改革委 统计 25 / 筛选 26** —— 多出来的是：

```
司法部 国家发展改革委关于《中华人民共和国民营经济促进法（草案征求意见稿）》公开征求意见…
```

牵头是司法部（统计记在司法部名下），发改委是参与方（筛选能筛到）。

**如果直接把数字链到参与口径**，用户点进去看到条数比表格多，会以为统计出错。

## 修复

- **新增 `lead=1` 口径**（`ListNoticesFilteredOptions.leadAgencyOnly`）：`agency_keys`
  是「|牵头|参与…|」，牵头口径的模式串是 `|X|%`（参与口径是 `%|X|%`）。顺带给机关名
  做了 LIKE 字面量转义 + `escape '\'` —— 此前 `?agency=%` 会命中所有联合发文行，
  与 issue #33 是同一类问题（用户输入被当通配符）。
- **首页支持 `?agency=X&lead=1`**：筛选摘要显示「机关（牵头）：X」，并给一行口径说明
  与「改看含该机关参与的全部条目」的一键切换 —— 否则用户只看到条数变少、不知道口径变了。
- **统计页机关名变成钻取链接**（带 `lead=1`）：表头说明改为「按**牵头机关**聚合…各部门
  之和等于条目总数…点击机关名可查看该机关牵头的条目」，链接带 `aria-label` 说明条数。
- **月度趋势表刻意不加链接**：首页筛选表达不了「某月」这个维度，链过去名不副实
  （要做得先给筛选加月份维度，属另一件事）。

## 验收

- e2e 新增 2 条：
  1. 两套口径的区分 —— 参与口径含联合发文、`lead=1` 不含、牵头机关带 `lead=1` 含，
     且口径说明与切换入口都在；
  2. **不变式**：遍历统计页每一行，点进去的条数必须等于表格上的数字（fixture 里正好
     有联合发文，能真正区分两种口径）。
- 线上核验：**16 个机关全部一致（16/16）**；发改委 `lead=1` → 25（= 表格数字）、
  默认口径 → 26；口径说明与切换链接均渲染。
- 红色证据：线上旧代码 `?agency=中国人民银行&lead=1` 忽略 lead（返回 1 条、无口径说明）、
  `/stats` 无任何钻取链接（`agency-total-link` 不存在）。
- 顺带修好被 markup 改动影响的 stats e2e 解析器（允许机关名被 `<a>` 包裹并取出 href）。
- 本地：单元 103 + E2E 163 全绿，typecheck / lint 干净。
