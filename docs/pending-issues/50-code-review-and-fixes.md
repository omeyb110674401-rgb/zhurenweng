# 全量代码评审（两轴）与修复

**缘起**：用户要求「review 代码质量」。按 `/review` 的规矩跑两轴 —— **规范**（是否遵守本仓
已写下的规矩）与**规格**（是否忠实实现原 issue / PRD）—— 两轴各由一个独立子代理并行完成，
我逐条核验承重结论，然后按用户「全量修复」的要求把 11 条发现全部落地（含核验后否掉的假阳性）。

评审基线：`origin/main...HEAD`（34 个提交、78 个文件、+5034/−221）。

## 一、修复清单（按用户可见性排序）

### 1. 牵头口径在筛选表单里静默丢失（线上可复现，最该先修）

- **现象**：从统计页「各部门公示量」钻取进来的是 `?agency=X&lead=1`（牵头机关口径），
  表单的隐藏字段只保留了 `category` / `from` / `to` / `period` —— **漏了 `lead`**。
  用户不改机关、只填个关键词点「筛选」，`lead=1` 就丢了，口径退回「任一参与机关」，
  条数当场变化（线上实测发改委 25 → 26）。
- **与 #39 同类**：#39 修的是「机关下拉在说谎」，这次是「表单提交在说谎」——同一类缺陷
  的第二个出口。
- **修复**：`src/app/page.tsx` 补 `lead` 隐藏字段，且只在**带机关**时写
  （裸 `lead=1` 不改变任何结果，见 `buildFilterHref` 的同款守卫）。
- **验收**：e2e 新增「钻取进来的牵头口径在筛选表单里被留住」——正向断言隐藏字段存在、
  列表页摘要写着「机关（牵头）：」，反向断言没带牵头口径的页面不写这个字段。
  **红检**：删掉该隐藏字段 → 重建 → 新用例当场变红（`ℹ fail 1`）。

### 2. 邮件 HTML 里 `href` 的动态值没转义

- **现象**：`src/lib/mail.ts` 自己立的规矩是「凡是插进 html 正文的动态值都必须过
  `escapeHtml`」（#37），标题与截止日期都过了，**`notice.url` 没有** —— 而它来自源站。
  源站 URL 里只要出现一个 `"` 就能跳出 `href` 属性，把抓来的第三方数据变成提醒邮件里的
  标记与链接（钓鱼面）。同一处 `detail` / `unsubscribe` 也一并补齐。
- **修复**：三个 href 全部过 `escapeHtml`；模块头的规矩补一句「包括 href 里的动态值」。
- **验收**：单测新增用例（URL 里带 `"onmouseover="`），**红检**还原转义 → 新用例变红。

### 3. `src/db/repo/stats.ts` 里的裸 NUL 字节（文件长期不可评审）

- **现象**：第 107 行的 Map key 模板串里有一个**真实的 `\x00` 字节**（不是转义写法）。
  后果不是运行期 —— 是**评审期**：git 把整个文件当二进制（diffstat 显示
  `Bin 8427 -> 8213 bytes`），连 Read 工具都拒读（`Unsupported or binary text encoding`）。
  这个文件里的任何改动，在 diff / blame / 任何文本工具里都**看不见**。
  更隐蔽的是它的头部注释还宣称「不使用任何方言专属日期函数」，而同一批提交里
  `notices.ts:185` 新增的正是 `julianday` / `::date` 的方言分支 —— 同一个问题两处给出
  互相矛盾的答案（ADR-0001 只允许「一处且有记录」）。
- **修复**：`\x00` → 转义写法 `\u0000`（语义不变，仍是不会与数据冲突的分隔符）；
  头部注释改写为「本模块不含方言函数；唯一那处分支在 notices.ts 的 periodDaysExpr，
  两者日历口径同为 UTC 日历日差，不是两个口径」。
- **附带发现**：这个文件也是**全仓唯一**一个以 CRLF 存储的文件（320 个受跟踪文件里
  319 个是 LF）—— 于是「改一行」在 diff 里表现为 215 行全变。已归一为 LF。

### 4. 多词搜索在三条路径上有三种语义

- **现象**（线上实测）：`医疗保障 不存在的词xyz` 在搜索页返回 **4 条**（等于只搜了
  「医疗保障」）—— 生产 Meilisearch 没带 `matchingStrategy`，默认的 `last` 会把对不上的
  词逐个丢掉；本地 FTS5 路径对同一查询返回 **0 条**；PG 兜底路径拿**整串**当子串匹配，
  多词输入必然零命中。同一个查询三条路径三种答案（#32 的教训）。
- **规格依据**：#33 定的规矩是「多词 = 全部词」，而且只落在首页筛选上；搜索页的注释
  还把差异写成「刻意保留」—— 与 #33 相反。
- **修复**：
  - `splitSearchTerms`（`search-text.ts`）：按空白拆、小写归一、丢空词、限量 10 —— 三条
    路径共用同一份「一个词怎么算」；
  - Meilisearch 请求加 `matchingStrategy: 'all'`；
  - PG 兜底改为逐词 ILIKE + 应用层 `matchesAllTerms`（并顺手修掉「复核用区分大小写的
    `includes`，含大写的词会被粗筛选中又在复核里丢掉」）；
  - 首页筛选 `keywordCondition` 改用同一个 `splitSearchTerms`。
- **验收**：单测新增 `splitSearchTerms` / `matchesAllTerms` / 请求形状三组；
  **红检**去掉 `matchingStrategy` → 3 个用例变红（含既有的请求形状用例）。

### 5. 天数差两份实现（其中一份还会把坏日期静默归一）

- **现象**：`stats.ts` 自己写了一份 `calendarDaysBetween`（正则截前 10 位 + `Date.UTC`，
  **不校验月日范围**），`dates.ts` 另有一份倒计时实现，`DAY_MS` 两处各定义一遍。
  两份只在日期严格是零填充 `YYYY-MM-DD` 时一致：`2026-13-45` 会被 `Date.UTC` 静默归一成
  2027-02-14，算出一个看着合理的「公示期长度」，而日历口径的真相是「这个日期不存在」。
- **修复**：`dates.ts` 导出唯一的 `calendarDaysBetween`（走 `normalizeDateText` 的回读校验），
  `daysUntil` 也改为它的调用方；`stats.ts` 删掉自己那份与 `DAY_MS`。
- **顺带把「PG 侧坏日期抛 500」这条潜在风险收口**：所有适配器与两个后台写入路径产生日期
  都走 `normalizeDateText`（已逐个核对），坏日期**进不了库**；`notices.ts` 的
  `periodDaysExpr` 因此不必再加方言专属的形状守卫（那会把「唯一一处方言分支」撑大）。
- **验收**：单测新增 5 组（含 `2026-13-45` / `2026-02-30` / `2026-04-31` → null）。

### 6. 爬虫 UA 散在 6 处

- **现象**：`worker/jobs/crawl-notices.ts` 与 5 个 `scripts/*.mjs` 各自硬编码同一串 UA，
  其中联系地址是写死的域名，而 `site-url.ts` 明确从 `SITE_URL` 取 —— 换域名时爬虫与
  审计脚本会继续指着旧主机（2026-09-21 GitHub 停用时就是这样：UA 里还写着已 404 的仓库地址）。
- **修复**：新增 `src/lib/site-identity.ts`（`SITE_ORIGIN` + `CRAWLER_USER_AGENT`），
  6 处改为导入；模块头写清**为什么它是常量而不是 `SITE_URL`**（UA 是给源站运维看的固定
  身份，开发机跑抓取也必须声明生产站点的联系地址）。

### 7. 统计页空机关行会给一个说谎的钻取链接

- **现象**：`?agency=` 会被首页当成「未传该参数」（`firstParam` 把空串视作未传），
  于是空机关名的行点进去是**未筛选**的全量列表 —— 数字与表格不符，违反 #36 的不变量。
  另有「`agency` 是复合串、`agency_keys` 为空」的旧行会被表格统计到、却落在牵头机关
  LIKE 之外。
- **修复**：`agencyDrillHref()` 对空机关名返回 `null`，该行退化为不可点（标签显示
  「未标注机关」）；顺手把 6 处 `{n > 0 ? <Link> : n}` 收成一个 `DrillNumber` 组件，
  **趋势表总计那格原先为了算个和还要在 JSX 里写立即执行函数**，可读性最差的一处随之消失。
- **线上核验**：16 行机关全部满足「点进去的条数 = 表格数字」（表格数字之和 178 = 收录总数），
  且**没有空标签行** —— 所以这条是**潜在**边界而非线上缺陷；SQL 那半（复合串 + 空
  `agency_keys`）**没有**投机性改动，见「未做」。

### 8. 统计页不再产出 `?month=` 别名

- **现象**：#48 已把 `?month=` 定义为只读兼容别名（老链接仍认），但页面仍在产出它。
- **修复**：趋势格子与月度合计改用区间写法（`from = to = 该月`）；e2e 的两处 href 断言同步更新。
- **验收**：e2e 断言「月度链接用区间写法，不再产出 `?month=` 别名」。

### 9. 部署通道：死脚本与过期文档

- **现象**：新增的 `deploy/deploy-33.sh` 请求的是本系列自己记录为 404 的 codeload 地址
  （2026-09-21 账号停用后这条通道就断了），写于通道断掉之后、从未被使用过；而
  `docs/deploy.md` 第 2 节仍把「服务器直接克隆」写成首选、第 8 节仍写 `git pull`。
- **修复**：删除 `deploy-33.sh`；新增 `deploy/README.md` 说明两种通道的现状与
  `deploy-NN.sh` 系列为何不可用（留档，别照着跑）；`docs/deploy.md` 第 2 节改为
  「A 当前不可用 / B 整包 / **C 增量（当前主用）**」、第 8 节同步。

### 10. 换行符：没有 `.gitattributes`，全仓唯一一个 CRLF 文件正是 stats.ts

- **现象**：`core.autocrlf=true` + 无 `.gitattributes` / `.editorconfig`，ESLint 也没配
  `linebreak-style` —— 工具链对换行符完全沉默。`stats.ts` 以 CRLF 存储，导致「改一行」
  diff 成 215 行；shell 脚本带到 Linux 侧还会因 `\r` 报 bad interpreter。
- **修复**：`.gitattributes`（`* text=auto eol=lf`）+ `.editorconfig`；`stats.ts` 归一为 LF。
  全仓 320 个受跟踪文件里只有它一个需要归一 —— 所以这次**没有**产生大批量的换行符改动。
- **核验过的假阳性**：评审说 `sync-files-local.sh`「先归一化再算 sha256，但发送原始字节，
  于是校验无意义」——**不成立**：脚本在**取哈希与生成载荷两处都做了同一份归一化**
  （`data.replace(b'\r\n', b'\n')`），校验与落地内容一致，无需改动。

### 11. e2e 列表解析器：12 处收成 1 个入口

- **现象**：12 个 e2e 文件各自写了一遍「按 `<li class="notice-item"` 切块」（两种写法），
  列表项一旦改标记要同时改 12 处，漏一处就是「解析不到 → 断言报出看不懂的错」；
  #49 只统一了数字提取。
- **修复**：`helpers/html.mjs` 新增 `noticeItems(html)`（匹配 `data-testid="notice-item"`，
  testid 才是本仓 e2e 的稳定契约），12 个文件改为调用它，字段提取仍留在各文件；
  顺手删掉 `status-freshness` 里「把已导入的 helper 又包一层同名本地函数」的冗余 wrapper。

## 二、核验后否掉的评审结论（3 条假阳性）

1. **`PERIOD_LABELS` 不是重复定义**：它是从 `PERIOD_BUCKETS` 派生的（注释还写明正是为了
   避免 #46 那种两份定义漂移），评审把「派生」读成了「另一份」。
2. **`sync-files-local.sh` 的校验没问题**（见上）。
3. **「半区间 + 别名会凭空造出区间」不成立**：旧实现的镜像守卫
   （`range.to === undefined ? 别名 : undefined`）在四种输入下与新实现**完全等价**
   （逐例推演 + 单测确认）。本轮仍改了写法，但它是**可读性重构**，不是行为修复 ——
   新用例是「不变量钉子」，不是缺陷回归，测试注释已按此改写。
4. 另有一条被**降级**：空机关行 / 复合机关行那两个洞，线上 16 行机关全部满足不变式
   （合计 178），属潜在边界而非线上缺陷。

**过程结论**：独立子代理会给出**看似合理但错误**的结论 —— 三条假阳性里两条来自规范轴。
核验成本远低于采信成本（每条只需读一遍对应源码）。

## 四、过程教训（本轮真踩了）

**红检的破坏性注入不能用空串当哨兵**：第一版脚本用 `good → ''`（删掉该行）做破坏，
但「修复一个已经是破坏态的文件」那条分支里 `d.replace('', good)` —— Python 对空搜索串
会把替换串插到**每个字符之间**，于是 `meilisearch-search.ts` 被写成垃圾。表现极具误导性：
测试**确实红了**（`ℹ fail 2`），但红的原因是**两个测试文件加载失败**（TS 语法错误），
而不是断言咬中了目标行为 —— `returncode != 0` 把「假红」也算成了咬中。
**规矩：破坏性注入的哨兵必须非空；红检必须看清「红在哪一条」，语法错 / 加载失败不算咬中。**
