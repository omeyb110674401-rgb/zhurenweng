# 统计页月度趋势表的数字全是死文本：缺的是「按月份」筛选口径

## 审计结论（2026-09-21）

| 检查项 | 结论 |
| --- | --- |
| **趋势表的钻取入口** | **缺陷（口径缺口）** —— 见下 |
| 聚合与排序仍用抓取口径的 status | **不改** —— issue #43 已评估：展示层（徽标 / 摘要 / 结构化数据）已按当前日期复核；库内 status 只影响首页把 open 排前（即将截止本来就在最前，无错位）、统计页（无状态分布）、提醒任务（只认 d7/d3），**不会产生任何错误的数字** |

## 缺陷：同一页上「机关」能点、「月份」不能

issue #36 给「各部门公示量」表的 16 个机关名加了钻取，并立下规矩：
**统计页每个数字都应可点开，且点进去的条数必须与表格数字一致**。但下面那张
「公示量月度趋势」表 —— 96 个格子 + 6 个月度合计 —— 全是纯文本。

缺的不是链接，是**口径**：首页筛选此前只能表达「领域 / 机关 / 关键词」，
表达不了「某月」（issue #36 与 #41 的记录里都写着「月份维度需要先定 URL 口径」）。
所以这一轮先把口径定下来，再把链接接上。

## 修复

**URL 口径**：`?month=YYYY-MM` —— 与统计页聚合同一口径（按**发布**月份）。

- `src/db/repo/notices.ts`：`ListNoticesFilteredOptions` 新增 `publishedMonth`，
  条件是 `published_at like 'YYYY-MM%'`（前缀匹配，与 `stats.ts` 的
  `substr(published_at, 1, 7)` 同口径 —— **两处口径不一致，「条数 = 格子」就不成立**；
  模式串仍走 `likeLiteral` 转义）；
- `src/app/_lib/home-query.ts`：`monthParam` 严格校验 `^\d{4}-(0[1-9]|1[0-2])$`，
  非法值一律不生效（与未知领域值同一处理）；`month` 计入 `hasFilter` ——
  于是自动获得 issue #41 的索引口径（筛选视图 `noindex, follow`）；
- 首页接线：`FilterState.month`、汇总文案「发布月份：YYYY-MM」、
  GET 表单里保留 month 的隐藏字段（否则一提交就把月份丢了）；
- 统计页：**非零格子**链到 `/?agency=X&lead=1&month=YYYY-MM`（机关 × 月份），
  **月度合计**链到 `/?month=YYYY-MM`（该月全部机关）；**零格子不链**（点进去是空态，
  没有信息量，也不给爬虫多造无界地址）；小计与总计不链 —— 它们是求和结果，
  首页筛选表达不了「最近 6 个月」这个区间。这些取舍写进了页面说明（读者知道
  哪些数字能点、为什么）。

## 验收

- 单元（140，新增 2）：`monthParam` —— 接受 `YYYY-MM`（补零必需），
  `2026-13` / `2026-00` / `2026-8` / `26-08` / `2026-08-01` / `2026` / `abc` / `%` /
  `2026-%` / 空串 / 纯空白 / undefined 一律不生效；`hasFilter` 计入月份（合法值 true、
  非法值 false）；
- E2E（181，新增 1，`stats.test.mjs`）：**全矩阵不变式** —— 趋势表每个非零格子的链接
  必须带「机关 + `lead=1` + 月份」，点进去的「筛选后共 N 条」必须等于格子数字，
  且列表页摘要里出现「发布月份：YYYY-MM」；月度合计链接只带月份、条数同样必须相等；
  零格子不得是链接；
  顺带修了两处既有解析器（格子内容自本轮起可能是链接，数字要先剥标签再取 ——
  直接找 `\d+` 会取到 href 里的 `month=2026`）；
- **红检两层**：① 去掉仓库层的月份条件 → 不变式当场变红（条数不再等于格子数字）；
  ② 把链接分支退回裸数字 → 红（「趋势表应有可钻取的格子，实际 0」）；
- 本地全量：单元 140 + E2E 181 全绿，typecheck / lint 干净；
- 线上核验（部署后）：统计页 **36 个非零格子 + 6 个月度合计**逐一点开比对 ——
  **42/42 条数一致**，且每张列表页都显示「发布月份：YYYY-MM」并带 `noindex, follow`；
  零格子确实不是链接；首页 / 统计页 / feed / sitemap / `?month=2026-08` 全部 200。

## 未做（有意）

- **小计 / 总计不链**：它们是「最近 6 个月」的求和，首页筛选表达不了区间；
  真要链需要 `from`/`to` 两个参数与对应校验，收益不大（上方「各部门公示量」表
  已经提供机关维度的入口），留作后续；
- **趋势表的机关行头仍是纯文本**：机关维度已由上方表格提供入口，且趋势行的
  「小计」是窗口内的和、与上方表格的全时段数字不同 —— 把名字做成链接容易让人
  以为「点进去就是这个数字」，宁可不做。
