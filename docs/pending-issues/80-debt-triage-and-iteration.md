### 四个驱动力（这才是「为什么这么迭代」）

1. **自我更正**：109 个提交里 **38 个（34.9%）**在更正更早的结论。12 个提交自己承认「假绿」。
2. **产品真相层**：每发现一处「页面在编」就下沉一层 —— 摘要编造 → 去读附件 → 附件读不全 →
   给说明留名额 → 体裁分刀。#79 是这条链的最新一环。
3. **外部约束**：GitHub 停用直接造出 17 个「记录落本地」提交 + 一条自建 base64 部署通道。
4. **先量再做**：版本链（线上 0 条）、附件名进检索（8.9%）、`?month=` 都是**量完决定不做**。
   这是这套流程里最健康的部分。

### 循环为什么没闭合（这是我实测出来的）

09-21 起：`docs` 主题 **41 个 > fix 37 > feat 26**；**47.7% 的提交根本不碰产品代码**。
但同一窗口新建了 **54 个产品文件**，7 项功能在生产实测可用 —— **不是空转**。

真正的成本在别处：**验证被做成了手艺，而不是门。**
`scripts/check-test-pins.mjs` 1,181 行 / 53KB / 111 条用例，**`package.json` 里 0 个调用者**，
83 个测试文件只钉了 36 个（**覆盖 43%**）。所以下一轮还会发现同类假绿 —— 循环因此不闭合。
