## 一、为什么要测这个

PRD 的数据模型要求公示状态是三态「征求意见中 / 已截止 / **已出结果**」，
而生产实测：`status='resulted'` **0 条**，标题含「反馈 / 结果 / 采纳」的条目也是 **0 条**。
两种解释完全相反：① 这些部委根本不发反馈结果 ⇒ PRD 该按实测收缩；
② 我们收了但没识别 ⇒ 该做回指。不测清楚就动手，两种情况里必有一种是白工。

## 二、结论：**「已出结果」是口径排除，不是没有数据**——但只在一家身上成立

- `src/sources/adapters/mot.ts` 的注释明写「状态位为空的包含『…公开征求意见反馈情况』（结果反馈）」
  并据此**过滤掉**（第 29-30 行、第 85 行）；
- `tests/e2e/sources-expansion.test.mjs:82` 还把这条标题当成"应当被过滤"的断言钉住了。

## 三、建议（待你拍板）

1. **不做完整的三态闭环。** 为一个半年一条、且只有一源确定有的东西去改状态机、
   建回指表、加呈现分支，代价与收益不成比例。
2. **把 PRD 的三态按实测收缩**为「征求意见中 / 已截止」两态 + **有则标注**：
   识别出结果类公告时标出来并尽量回指，识别不出也不谎称"没有结果"。
   （`src/lib/notice-brief.ts:195` 已经有 `意见反馈情况` 这个文档类型判定，接得上。）
3. 若要动手，最小实现只有一步：**让 mot 不再过滤反馈类条目**，并用
   「标题里的《草案名》+ 征求意见期」把结果公告挂回原条目（实测无回链，只能这么配）。
   代价：`sources-expansion.test.mjs` 那条"应当过滤"的断言要改，列表里会混进非征求意见条目，
   首页排序与状态口径都得复核 —— 所以这一步要先确认值不值。
4. 唯一值得补的探测：samr 的「结果反馈」栏目取一次样（1 次请求，需要该栏目的分页参数）。
   有货的话，上面的最小实现就变成两源。
