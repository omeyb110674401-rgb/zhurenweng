# PRD：主人翁 v2 —— 判读的合规审读门（带门扩）

> 本 PRD 由 2026-10-04 的 `/grill-with-docs` 拷问得出，19 项决定的台账、被作废的前提与残余风险
> 全部记在 `docs/pending-issues/91-l3-compliance-review-gate.md` 第八节。术语沿用根级 `CONTEXT.md`
> （「审读」与「人工复核」在那里正式分家）。

## Problem Statement

**行业专业档的读者看不到判读，而判读恰恰在那一档最成立。**

判读（「可能的争议点」）是全站唯一一段回答"这事跟我有没有关系"的内容。它今天只在**公众广域**档
渲染（受众面门控，2026-09-27 拍板"先只上公众广域 + 人工过一遍"）。可现场读数是反着的：

- 落库判读 **11 条条目 / 53 条判读文本**，其中 **6 条行业专业档条目（22 条判读）存着却一个字都不渲染**，
  5 条公众广域档条目在渲染；
- 行业档里最富的一条（CCAR-21《民用航空产品和零部件合格审定规定》，8 条判读）正是读者本人
  就在名单上的那种条目；
- 另有 **19 条行业专业档积压**：材料已在手（抽样验过重跑会喂进 1 份 / 7,205–7,974 字符条文），
  只是当初那次调用根本没问过 L2/L3。

不扩的理由也真实：判读说错的代价是**误导**，而"多走一步"正是判读的定义，所以界在哪说不清。
用户 2026-10-04 拍板：**带门扩** —— 扩到行业专业档，但渲染前必须由**合规性独立模型二次审读**、
有问题先改、改完才渲染发布。

而今天挡在这条路上的三件事，都是形状问题、不是意愿问题：

1. **渲染门是布尔谓词**。"审读后修改再发布"要求渲染的那一份文本是**审读后文本**，谓词交不出文本。
2. **没有第二路模型通道**。全进程只有一个 LLM 端口、由单一环境变量选择，"独立模型"没有容器。
3. **没有任何审读记录**，也没有任何东西能在生成侧重跑后判定"这条判读还被审读过吗"。

## Solution

新增**审读**这道门：每条判读在渲染前由一路与被审读内容不同来源的模型判定
**通过 / 改文本 / 剔除**，审读后文本与生成侧原文**并存**；渲染门只放行被**有效审读记录**覆盖的判读。

读者视角的结果：

- **行业专业档的读者开始看到判读**，且看到的那一句是被独立审读过的；
- **已经上线的公众广域判读不会因为新增这道门而消失** —— 存量在开门之前先批量审读完，避免
  fail-closed 造成空窗；
- 页面上**不出现任何"已审读"字样**：读者能核对的仍然只有原文，信任不建立在无法核对的元声明上；
- 某一条被判负时**只剔除那一条**，同一段里其余判读照常显示。

运营与维护视角的结果：

- **重跑即失效**：生成侧重跑后，旧的审读结论按内容指纹自动失配 ⇒ 该条判读退回不渲染，
  不会出现"没被审读过的文本配着别人的审读结论"；
- **判不出来就不显示**：审读超时、返回非法形状、压根没跑过，一律不渲染（沿用本仓既有的 fail-closed 纪律）；
- 审读规则由**指导模型**（构建期角色）穷举错误与误报后总结，落成能进单测与 pin 表的 `.ts`
  提示词 + `tests/` 里的错误案例库夹具 —— 改规则时撤掉实现会变红。

## User Stories

1. As a 行业专业档的读者（运输机场运营人 / 医疗器械注册人）, I want 看到"这处改动可能让我的什么被动了"的判读, so that 我能在事发前决定要不要去提意见.
2. As a 公众访客, I want 已经上线的公众广域判读不要因为新增一道门而消失, so that 我这次访问看到的东西和上次一样.
3. As a 公众访客, I want 我读到的那一句是被一路独立模型审读过的, so that 我据此行动的风险更低.
4. As a 公众访客, I want 页面上不出现"已审读"这类我无法核对的字样, so that 我对这段内容的信任仍然建立在能核对的原文上.
5. As a 公众访客, I want 某一条判读被审读剔除时同一段里其余判读照常显示, so that 个别问题不会连带藏掉整段.
6. As a 公众访客, I want 列表页的标记与详情页说的是同一件事, so that 我点进去不会发现那里什么都没有.
7. As a 站长, I want 生成侧重跑后旧的审读结论自动失效, so that 我不会发布一份没被审读过的文本配着陈旧结论.
8. As a 站长, I want 审读没跑成时宁可不渲染, so that "判不出来"永远不会被我读成"这条没问题".
9. As a 站长, I want 存量判读在开门之前先批量审读完, so that 开门那一刻线上不会出现一片空白.
10. As a 站长, I want 审读与生成走两路互不相同的模型, so that 复核不是自己确认自己.
11. As a 维护者, I want 审读提示词与判据住在能进单测与 pin 表的 `.ts` 里, so that 改规则时撤掉实现会变红, 而不是靠人记得.
12. As a 维护者, I want 错误案例库落成测试夹具, so that 规则改动之后重跑一遍就知道有没有退化.
13. As a 维护者, I want 渲染门仍然只有一个出口, so that 详情页与列表页不可能各判一次、各说各话.

## Implementation Decisions

### 术语与词汇

- 新概念一律叫**审读**（审读模型 / 审读记录 / 审读后文本 / 审读状态），**不用**「复核」指代它 ——
  「复核」在本仓已被**人工复核**（摘要转人工那条路径）占用。词表落在根级 `CONTEXT.md`。
- 审读状态取值互斥：**通过 / 已改 / 剔除**；没有有效审读记录的判读视为不可渲染。

### 审读记录（存储）

- 审读记录**独立落**，**不进 `ai_summary_json`**。那是渲染契约，往里加键会牵动读侧，且本仓有
  "存量条目掉回待人工复核"的先例。形态取既有先例的做法：**可空的独立列**，随摘要一起写、
  随重跑一起清（`summary_diagnostics_json` 就是这么立的）。
- 记录形状：每条判读一条记录，字段为
  **`quote` 指纹 / 生成侧 `text` 指纹 / 审读状态 / 审读后文本（仅"已改"）/ 审读模型 / 审读时间**。
  **不设"理由"字段**：本仓对"说不清凭什么"的字段一律不要，而"改了什么"已由原文与审读后文本并存
  本身可审计，多一个没人必须填的字段只会是空的。
- 迁移新增一列（可空、不回填），**双方言**，序号接在现有最后一个迁移之后；两个 journal 的
  `when` 保持单调。
- **判读本身不迁表**。逐条生命周期由审读记录承担，它按内容指纹挂在 JSON 里的判读上；
  不引入"稳定 id"，也不把判读搬去条款级表（那会在判据验证之前锁死存储形状）。
- 重跑清空摘要时**一并清空审读记录**，并沿用既有的"交还旧值"行为（重跑工具用得着）。

### 渲染门（唯一的判据出口）

- **受众面退出判读的渲染判据**。门从此只认"有没有有效审读记录"，不再看 `audience`。
  受众面继续管与风险无关的事（「影响谁」只在行业专业档渲染），但它**不再承担"内容可不可以见读者"**。
- 单一出口函数从**谓词**改形为**选择器**：输入判读数组 + 审读记录，输出**该渲染的判读数组或 `null`**。
  函数名一并改掉（返回文本却叫 `should…` 是名不副实，而本仓对"doc 与代码各说各话"很敏感）。
  它仍是**唯一**出口，详情页与列表标记都只经由它。
- **指纹匹配判定放在这个函数里**（不是放在调用方）：`quote` 指纹与生成侧 `text` 指纹**全等**
  才算有效审读记录。于是"重跑后失效"是纯函数可测的行为，不必为它立第二层测试。
- 投影规则：`通过` ⇒ 原文；`已改` ⇒ 审读后文本，原文不进渲染数组；`剔除` ⇒ 不进渲染数组；
  **无记录 / 指纹不匹配 ⇒ 全部不渲染**（fail-closed）。
- 空则 `null`（一条都不剩 ⇒ 整段不渲染，连标题都不出现），沿用既有空门。
- **审计差异靠"并存"**：原文与审读后文本各留一份，差异即审计材料。

### 审读的调用

- **第二路 LLM 端口**：新增独立的端口与环境变量族（审读侧专用），不复用生成侧那一套。
  今天"全进程只有一个端口、由单一变量选择"的现状**必须改**。
- **独立性**：审读侧与生成侧**不同厂商**，且审读侧走境内直连。生成侧本次**不动**（仍经境外中继）——
  也就是说本功能的效果是**不再增加新的出境调用**，而不是偿清既有的合规债。
- **来源**：审读的输入是判读四件（逐字引用 / 受影响主体 / 受影响方面 / 推断正文）**加上**
  由 `quote` 定位回附件后取出的**原文邻域**。没有邻域，"是否超出原文 / 是否与原文相悖 /
  是否漏掉免责或例外"这三条都判不了（只喂引用会让第一项退化成循环判据）。
- **邻域长度落成 `.ts` 里的具名常量**，只此一处；具体取值由指导模型的流程给出，本 PRD 只钉形态。
- **调用粒度：每条条目一次调用**（一次审读该条目的全部判读）。理由：审读要看原文邻域，而一个
  条目里的多条判读常出自同一份附件；调用次数从"按判读约 163 次"降到"按条目约 25 次"；
  一次调用还能看见条目内的一致性。**若指导模型给出的流程要求逐条调用，以流程为准，但必须回报。**
- **审读只减不加**：`quote` 与条目集合冻结，只许给出 通过 / 改文本 / 剔除。
- 生成侧的超时 / 非法形状处置**沿用既有 fail-closed 纪律**：不渲染，可重试。
- 审读记录为空或缺失时，量具（`deploy/audit-l3-reach.sql`）里"能不能渲染"那一条要**与新门同源**，
  否则量具与页面各说各话。

### 指导模型（构建期角色，不进运行时）

- 职责：穷举可能的错误与误报、据此总结审读提示词与审读流程，并留下错误案例库。
- **产出落点**：审读提示词与判据进 `.ts`（可导出、进单测、进 pin 表）；错误案例库进 `tests/` 夹具
  （每条含输入判读 + 原文邻域 + 期望结论）。**产出以人提交的代码与夹具形态入库，谁提交谁负责。**
- 它不参与线上任何一次判定，也不进入交付物本身的运行时。

### 存量、回填与开门顺序

- **范围**：6 条行业专业档存量（22 条判读）与 19 条积压**一起重跑**（同一条路径），跑完统一送审读；
  `#41`（存量回填）并进同一次回填，避免同一件回填做两遍。
- **工具前置**：重跑工具今天判的是"`keyPoints` 里有没有带出处的一项"，**判不出"缺 L2/L3"**，
  会跳过最该重跑的那一批。必须先补这一档判据（"缺 L2/L3 就算候选"），而不是靠 `--ids` 点名
  —— 回填的可复现性要求它是"一条判据跑出来的"，不是一份手抄的 id 清单。
- **迁移顺序（硬约束）**：**门翻转必须晚于存量审读完成**。没有这一条，fail-closed 会让今天在线的
  5 条公众广域判读在审读跑完之前集体消失。
- 生产写入按纪律**逐次授权**，不预先承诺时点。

### 页面文案

- 列表标记措辞**一字不改**（「含本站推断（非官方）」/「含改动对照」），详情页**不加**"已审读"字样。
  审读不改变"它是推断"这个事实，而"非官方"那三个字是最要紧的。
- 审读状态只在诊断与审计面可见。

### 必须同步改的接线

改了渲染门的形状，就有一组东西必须跟着改，漏一处就是"列表承诺了详情页不存在的东西"：
详情页的调用点、列表标记的调用点、两者**逐格一致**的那条契约测试、以及 pin 表里那条以
调用语句为靶点的 pin（靶点要跟着搬，这是它存在的意义）。

## Testing Decisions

**什么算好测试**：只测**外部行为** —— 也就是"读者会不会看到这一段、看到的是哪一句"。
门是纯函数、判据在 `.ts` 里，所以这些行为全都能用 `node --test` 直读源码断言，不需要渲染页面、
不依赖构建产物。反面例证是本仓已抓到三次的老毛病：判据落在 `.tsx` 或 e2e 上，
撤掉实现却撤不出红（e2e 跑的是 `.next` 构建产物）。**不测内部结构、不测函数被调用的次数。**

**测试缝：一个 —— 渲染门的返回值。** 它今天已经是详情页与列表标记共用的唯一出口，本功能的全部
读者可见后果都由它决定；审读的判定与存储在它上游，最终**必须表现为它的输出**，这正是"只测外部行为"
该有的位置。不新建第二层测试基础设施：审读记录的落库与清空用既有的摘要 repo 缝补断言
（它俩已有"重跑清空并交还旧值"的既有行为可依），端到端沿用既有的 stub LLM 路径多回答一路。
**不把缝放在 worker 边界** —— 那一层测得到"审读调用发生了"，测不到读者看见什么，而风险全在后者。

**要被断言的外部行为**（每条都对应一个决定）：

1. 有"通过"记录 ⇒ 渲染原文；
2. 有"已改"记录 ⇒ 渲染审读后文本，原文**不出现**；
3. 有"剔除"记录 ⇒ 该条不出现，同一段其余照常；
4. 没有任何记录 ⇒ **不渲染**；
5. 指纹不匹配（生成侧重跑过）⇒ 视为无记录 ⇒ 不渲染；
6. 指纹全等（内容一字未变）⇒ 旧记录**幂等有效**（同一份内容、同一份结论）；
7. 受众面**不再是判据**：行业专业档 + 有效记录 ⇒ 渲染；公众广域 + 无记录 ⇒ 不渲染；
8. 一条都不剩 ⇒ 返回 `null`（整段连标题都不出现）；
9. 列表标记与门的结论**逐格一致**（扩展现有那条穷举契约测试，把审读状态加进输入空间）；
10. 审读记录随摘要落库、随重跑清空（用既有 repo 缝）；
11. 源码接线：两个调用点都调用同一个门；审读提示词住在 `.ts` 里；门不再引用受众面。

**类似先例**（照它们的形状写，不另起一套）：`tests/unit/summary-impacts.test.mjs`（门的真值表）、
`tests/unit/notice-marks.test.mjs`（两个门逐格一致的契约测试）、`tests/unit/impact-overview.test.mjs`
（"判据抽 `.ts` 而不是写在页面里"的同一理由）。错误案例库夹具与既有 `tests/unit/*.test.mjs` 夹具风格对齐。

**门**：本地 `npm test`（`pretest` 会重写 `src/` ⇒ **绝不与其它 agent / 构建并行**；e2e 含 `next build`）；
CI 按批推、一次推送一次 run、不拿 CI 当测试渠道；提交信息里提到跳过标记时必须拆开写。

## Out of Scope

- **审读结果向读者展示**（含列表标记的措辞改动）—— 决定：不露。
- **审读分布读数与"门空转"告警**。整条链在本 PRD 之后**没有人工检查点**；审读一路说"通过"时，
  页面照常渲染、fail-closed 不触发、标记照常打，**没有任何地方会报错**。这是本 PRD 最大的已知缺口，
  按决定不在此列解决。
- **把判读迁到条款级表**（86 的目标形态）。86 那条触发条件（"某一条判读要单独改 / 单独重跑"）由
  审读层在不迁表的前提下满足。
- **生成侧换境内直连**（#33）。本功能只保证不再新增出境调用。
- **人工通读判读 / 人工标注**（#38 已关闭）。
- **召回率与误报率的统计口径**：判决集方案已被替换为"由指导模型穷举错误案例"，不存在统计口径。
- **人工构造对抗样本集**。
- **受众面重判与「影响谁」的门控**（不在本刀）。
- **抓取侧**：新源、附件下载名额、正文窗口（都是另一条判据）。
- **审读后文本的额外约束**（长度契约、禁词、必须带理由）—— 决定：文本自由，只冻结引用与条目集合。
