## 四、硬约束（写进设计，不许违反）

1. **渲染门的唯一出口是 `shouldRenderImpacts`**（`src/lib/impact-display.ts`）。
   列表标记（issue #87）也调它 ⇒ **复核门必须加在这一个函数里**，否则列表页会重新开始承诺
   详情页不存在的东西 —— 那正是 #87 的全部风险，它在生产上被逐条实取验过"**0 条不一致**"。
2. **只能说"有"，不能说"无"**（#87 定的）：复核未过 / 复核没跑 / 判不出来的，一律**不打标**，
   也不写任何评论性文字（"暂无判读"会变成对内容质量的评语，还会把门控泄露成内部口径）。
3. **AI 生成标注不许因为"复核过"而削弱**（政务敏感面；`docs/prd/v1.md` 第 49 条）。
   复核本身若是模型，页面仍须写明这是**本站 AI 推断、非官方表述、可能错**；
   最多再加一句"已过自动合规复核"，**不能**把免责声明替换掉。
4. **fail-closed**：本仓既有纪律是"判不出来就不给它加码"（`shouldRenderImpacts` 对 `unknown` 不渲染）
   ⇒ 复核失败 / 超时 / 返回非法形状 ⇒ **不渲染**。
5. **判据留在 `.ts`**（能进单测与 pin 表）。`.tsx` 里的分支钉不住 —— e2e 跑的是 `.next` 构建产物，
   撤 `src/app/**` 撤不出红（本仓为此栽过多次）。

## 五、待拷问（下一会话的第一批问题）

### A. 把"合规性"具体化（现在这个词太宽，宽到没法实现也无法钉）

- A1 是否**超出原文**：判读"比引用多走一步"是它的定义、不是错。要定的是**多走多远算越界**
  （过目清单已点名 4 处"推断超出引用"）
- A2 是否**与原文相悖**
- A3 是否**对政策/部门作定性**（政务敏感面）
- A4 是否**指向具体主体的负面评价**（企业 / 个人名誉）
- A5 是否**构成法律意见**
- A6 是否**把"可以"读成"必须"**（漏掉原文的免责 / 例外）
- A7 复核输出形状：`通过` / `修改后通过（给出修订文本）` / `不通过（丢弃）`？
  要不要**留复核前后的差异**做审计？本仓对"说不清凭什么"的字段一律不要（#58 删「调度配置」）

### B. 独立模型是谁

- B1 生成方是 `mimo-v2.5`，且这条通道**经境外中继**（`FOLLOWUPS` 第一节 / issue #33）
- B2 **推论：#33 从"合规债"升级为本功能的前置依赖** —— 复核模型本身应当是**已备案国产模型直连**，
  否则出境调用从一次变两次，且"合规性复核"这件事的说服力自相矛盾。
  缺的是一个 `GLM_API_KEY`（经 `deploy/set-env-keys.sh` 落 `.env`，不进仓库、不进对话）
- B3 "独立"要不要**锁不同厂商**？同源偏差（同一模型复核自己的输出往往只会确认）正是要"独立"的原因

### C. 失败模式

- C1 超时 / 返回非法 JSON ⇒ 不渲染（可重试）—— 确认一次
- C2 复核说"这一条不通过" ⇒ **逐条剔除**还是整块不渲染？
- C3 复核**只能删或改，不许新增**（防止复核模型自己造判读）
- C4 未通过的条目在库里怎么表达（不留半成品）

### D. 渲染门与可见范围

- **D1 ⚠️ 一个必须先拍掉的矛盾**：现在 5 条 public 判读是**无复核直接渲染**的。
  带门扩之后若"行业档要复核、公众档照旧免复核"，就与当初"只上公众广域"的理由
  （判读说错的代价是**误导公众**，公众档风险**更高**）**正好相反**。三条路：
  全员送复核 / 公众档免复核并写明理由 / 两档同门但复核强度不同
- D2 扩到哪些档：只 `sector`，还是 `unknown` 也给？（未判定那 1 条）
- D3 「已复核」要不要**显示给读者**（见硬约束 3）
- D4 已截止的条目要不要也渲染（#87 已定"有就显示"）—— 与复核门组合后是否仍成立

### E. 存量与范围

- E1 那 6 条已落库的 sector 判读（22 条）**先送复核**，还是**重跑再复核**？
- E2 19 条 sector 积压（只缺 L2/L3）要不要一起做（重跑 + 复核）
  —— **与 #41 并条**，否则同一回填做两遍
- E3 复核是**每条条目一次调用**还是**每条判读一次**（成本 / 延迟；免费档约 1 分钟/条）

### F. 与既存决定的冲突检查

- F1 **#38（人工过一遍）怎么办**：用户选的现在是**模型复核**。人工过目还要不要？
  见第一节末尾那个用法（清单当判例）
- F2 见硬约束 1
- F3 列表标记措辞「含本站推断（非官方）」在"已复核"后要不要改？

### G. 命名

「复核」在本仓**已被"人工复核"占用**（`summary_status` 的转人工路径、`src/app/admin/review/`、
`MANUAL_SUMMARY_MODEL`）。新东西是**模型对判读的合规复核**，两个概念不能共用一个词

### 8.3 新增的硬约束（接到第四节 1–5 之后）

6. **审读记录独立落**，不进 `ai_summary_json`（那是渲染契约；#85 的先例是往里加键会牵动读侧）。
7. **审读层可抛弃**：生成侧重跑 ⇒ 指纹不匹配 ⇒ 该条判读的审读记录失效 ⇒ **不渲染**。
   审读不覆盖生成侧产物，重跑也不"继承"上一轮的审读结论。
8. **审读只减不加**：`quote` 与条目集合冻结，只许给出 通过 / 改文本 / 剔除。

10. **受众面退出判读的渲染判据**；`shouldRenderImpacts` 成为唯一出口的**选择器**
    （返回该渲染的文本或 `null`），不再是谓词。
11. **审读提示词与判据进 `.ts`，错误案例库进 `tests/` 夹具**（硬约束 5 的延伸）。

### 9.8 量具自己也要被量（2026-10-05，只写不部署；**这一批随第二批推**）

上面那份运行手册把 C-2（逐条实取对账）当成唯一的线上判据，而**本机跑不了它**：
没有 Postgres、没有 Docker，`deploy/audit-l3-reach.sql` 只能靠肉眼读。于是这一轮补的是
"跑不了的东西怎么被钉住"——三件，全部落在仓库里、全部有实测变红的证据：

1. **`tests/unit/audit-l3-reach-sql.test.mjs`（新）**：直接读那个 `.sql` 的文本，量四件事：
   ① 它自称"只读"（除 `create temp view` / `create function pg_temp.` 外不许出现任何写动作）；
   ② `$$` 成对、括号平衡；③ 它引用的 `impact_review_json` / `summary_diagnostics_json`
   在 postgres schema 与迁移里真的存在；④ 第 5/6/9c/12 节与两个验收数（缺口、错挂）还在。
2. **尺子同源是"读出来比的"，不是抄一遍**：从 SQL 里把 `pg_temp.zw_fingerprint` 的四步
   `regexp_replace` **解析出来**翻成 JS 链，再与 `quoteFingerprint` 逐例比 —— 而且引号字形集合
   是从 `normalizeQuoteMarks` 的源码里读的。于是"加一个字形只改一边""少一步归一"都会当场变红。
   门的判据同理：SQL 里那份结论白名单**不是与文档对齐，而是与 `impactsToRender` 的实际行为逐值对齐**
   （对每个结论真的调一次门，看它放不放行），另外钉"两个指纹都要比""受众面不许回到这一段"。
3. **详情页投影的 e2e 四条**（`tests/e2e/notice-genre-badge.test.mjs`）：`已改` ⇒ 页面出现审读后文本
   而**生成时那句话一个字都不出现**；`剔除` ⇒ 只去掉那一条、其余照常、概览计数按过门后的条数；
   全部剔除 ⇒ 整段不渲染；**生成侧重跑改了 text** ⇒ 旧记录指纹对不上、自动不渲染。
   这几条此前只有纯函数单测，而"判据对、页面没接上"正是本仓反复栽过的那类断线。

**如实记两条边界**（别把这一节读成"线上行为已验证"）：

- 上面那份 JS 等价实现是**SQL 文本的意思**，不是 Postgres 的 regexp 引擎 —— 它拦得住"代码侧
  改了尺子而 SQL 没跟上"，拦不住"真库里 regexp 行为与理解不同"。真库那一遍仍然是 §9.7 的 C-2。
- 已知一处残留差异：JS 的 `\s` 覆盖 NBSP 等 Unicode 空白，而 SQL 那层只列了 ASCII 空白与全角空格
  （**方向是 SQL 更保守**：它会把"只差一个 NBSP"的两段判成不同 ⇒ 少渲染，而不是错渲染）。
  这一条写成了可执行断言：哪天补上 `\u00A0`，那条断言会提醒把它改成相等、并删掉文件头注里的说明。

**施工时踩到的两个坑（写给下一个人）**：① SQL 里那一格是 `[[:space:]　]+` —— POSIX 类写在
**方括号里面**，按 `[[:space:]]` 去替换**静默不匹配**（第一次就是这么写的，断言红了才发现）；
② 校验"这一段里不许有受众面"时，锚点若取文件头那句「能不能渲染」，切片会跨过 `base` 里的
`n.audience` ⇒ 假红。所以取的是 `as renderable_impacts` 往前最近的一个 `(select count(*)`。

**本机预演**（B-1 那条命令的同一条路径，只是库不同）：拿本地开发库跑了一遍只读模式
`DB_DRIVER=sqlite DATABASE_URL=./data/zhurenweng.db node scripts/review-impacts-now.mjs` ——
输出是"有判读的条目 1 条 / 判读 6 条：覆盖 0 条，**缺口 6 条**"并逐条点名列出了引用与推断。
它证明的只有"这条命令在真数据上跑得通、缺口逐条点得出来"；**生产库里缺口是多少仍是未知**
（那正是 B-1 要贴回来定批次的那个数）。

**门（本地实跑）**：pin 自证 **247/247 红**（本刀 +4，全部对着上面那份 SQL 的四种漂法：

### 9.9 真实模型金丝雀（2026-10-05，**在本地开发库上跑通了**；生产仍未动）

用户给了 DeepSeek 的 key（⚠️ 见文末那条安全提醒），于是 #50 的"真模型金丝雀"在**本机**先跑了一遍：
`review-impacts-now.mjs --apply --ids 0b00deff`，库是本地开发库 `data/zhurenweng.db`，
数据是真数据（《反网络暴力法（征求意见稿）》，1 条条目 / 6 条判读）。

**第一跑就失败了 —— 而它失败得"看不出来"**（这正是金丝雀要抓的东西）：

- 报出来的是 `invalid-shape：审读响应缺少 choices[0].message.content 文本`，
  看着像"模型没吐东西／提示词要改"；
- 真因是**我们的两个数太小**：审读侧这一档是**推理模型**，推理 token 与正文**共用同一个预算**。
  实测同一条请求：`deepseek-v4-pro` 花 12,824 个推理 token（合计 13,380），
  `deepseek-flash` 花 3,387–5,523 个；而缺省超时是 60 秒、又**没给输出上限** ⇒
  响应被超时掐断/预算被推理吃光，而 `json().catch(() => null)` 把它吞成了一句形状错。

**三处修复（都落在仓库里，都有钉）**：

1. **输出上限显式给、且可配**：新增 `IMPACT_REVIEW_MAX_TOKENS`（缺省 **16384**）。
   给 8192 时实测仍会 `finish_reason=length` + 空正文（推理长度一跑一变：5.5k–12.8k token 都见过），
   给 16384 两次都 `stop`、正文完整（v4-pro 79 秒 / flash 17 秒）。
2. **超时缺省 60 秒 → 180 秒**（`IMPACT_REVIEW_DEFAULT_TIMEOUT_MS`）。
3. **形状错不许吞证据**：正文先读成文本再自己解析 —— "读到一半断了"归**传输错**（超时/网络），
   "不是合法 JSON"才是形状错；空正文的错误里必须带 `finish_reason`、推理字数、`completion_tokens`
   （第一跑就是因为没有这三个数才误诊）。修完当场看得见：`finish_reason=length，推理正文 14105 字，completion_tokens=8192`。

**修完之后**：`审读完成：送审 6 条 / 采信 6 条`、`写入审读记录 6/6`（**通过 3 / 已改 3 / 剔除 0**），
86 秒；再跑一次只读 ⇒ `覆盖 6/6，缺口 0`（这就是 #51 的验收判据）。
摘要那一列**一个字节没动**（3805 字节、`summary_model` 仍是 `mimo-v2.5`、诊断仍是那次生成的 v2）。

**顺带把 C 步在本机预演了**（这是这次最有价值的一步）：库里那条条目受众面是 `public`、
改造前**一条审读记录都没有** ⇒ 在翻转后的门下面它本该**整段消失**（正是"#51 必须早于 #52"
的理由）。补上真审读记录之后：

- 详情页出现「可能的争议点」与 `summary-impacts`，概览行 `共 6 处：2 处可能的不利后果 ·
  2 处可能被规避或滥用 · 2 处新增的义务或成本`；
- **三条「已改」的审读后文本逐条进了页面**（`原文不出现` 那一支在真数据上成立）；
- 列表页标记 `impacts`（"含本站推断（非官方）"）也出来了 —— 列表与详情页读的是同一个门。

**如实记边界**：这是**本地开发库**上的真模型金丝雀，**不是**生产库；生产那一遍（A/B/C）
仍要按 §9.7 逐次授权执行。另外本地那条条目的附件正文不在库里（`notice_attachments` 0 行），
所以这一跑里模型的"原文邻域"是空的 —— 它证明的是**链路通**（真 HTTP → 解析 → 指纹落库 →
门放行 → 页面渲染），**不是**判断质量；生产库里邻域有料，结论分布可能会不一样。
