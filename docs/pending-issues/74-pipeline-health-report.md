# issue #74：把这几天反复现写的产物核查固化成一条命令

前因是一条链：#68 每日备份 cron 从未触发 → #70 提醒/通知实际发出 0 封、CI 早已停摆 →
#71 备份失败只写进没人读的日志 → #72 检索索引与点击口径 → #73 订阅闭环能给多少东西。
每一次都在现写一段 SQL / 现跑一个探针。**那说明缺的不是查询，是一个会周期性逼问
"今天有没有产物"的清单** —— 判据散在对话里就会腐烂：阈值没人复查、结论没人重算。

这一轮把它做成三件东西：`src/lib/pipeline-health.ts`（判据，带类型、可单测）、
`scripts/audit-pipeline-health.mjs`（取数 + 打印 + 退出码）、`tests/unit/pipeline-health.test.mjs`。

## 一、三条设计决定，都来自这两天踩过的坑

1. **四态，`unknown` 不许折叠成 `ok`**。#68 的根因就是拿 `crontab -l` 与 `is-active crond`
   当验收 —— "没有反证"被当成"通过"。所以探针看不到备份目录时报 `unknown`，并写明为什么。
2. **需求侧事实判 `warn` 不判 `fail`**。0 个可发订阅者、0 次点击都不是故障；判成 fail 会让人
   去修一条本来正常的路径。但它们必须出现在同一张表里 —— #70 那两个 0 行之所以来回看了两轮
   才分清"路径坏了"和"没人可发"，就是因为这个数没被单独摆出来。
3. **总结论 fail 优先**，不被一堆 `ok` 平均掉。

## 二、生产实测（2026-09-25 03:31 UTC，只读，未改任何数据）

```

  ✓ ok      抓取新鲜度：最近一条新收录 15.3 小时前（阈值 48 小时）

  ✓ ok      近 7 天出站点击：113 次（0 次是需求侧事实，不判故障）
  ✓ ok      检索索引可搜性：抽样 12 条，搜不到自己的 0 条
```

跑法（备份目录不挂进来就只能是 `unknown`，这是刻意的）：

```bash
docker compose run --rm \
  -v /opt/zhurenweng/scripts/audit-pipeline-health.mjs:/app/scripts/audit-pipeline-health.mjs:ro \
  -v /opt/zhurenweng/src/lib/pipeline-health.ts:/app/src/lib/pipeline-health.ts:ro \
  -v /var/backups/zhurenweng:/var/backups/zhurenweng:ro \
  worker node scripts/audit-pipeline-health.mjs
```

重构后两份脚本都在生产上跑过（同一份 `auditIndexSampling`）：健康清单抽样 12 条 0 漏，
专用审计按缺省 `--stride 8` 抽样 24 条也是 0 漏 ⇒ "共用一份"不是注释里的说法，是跑过的。

## 三、读这张表时要带的三句限定

1. **dump 那 1.3 小时是今天我用一次性 cron 条目实测触发留下的**（#68 的验收），今晚 19:30 UTC
   才是装好之后第一次"自然"运行。所以这一格今天证明的是"cron 路径能跑通"，不是"已连续每天在跑"。
   明早再跑一次本命令，才拿到那条独立证据。
2. **近 7 天 113 次点击里有 46 行是仓库自己判定为机器点击、待清未清的**（FOLLOWUPS 的
   「机器点击清理」那条）。引用这个数当"读者量级"时必须带这句，否则就是在夸大需求。
3. `检索索引可搜性` 与 #72 那份专用审计**共用同一个 `auditIndexSampling()`**。两处各写一份的话
   迟早一个严一个松 —— issue #50 修过一模一样的病（同一个查询在三条路径给出三种结果）。

## 四、未做（有意）

- **没接定时告警**（`fail` 时发信）。#71 那条通道现在可以复用了，接上只是一行 cron；
  但 #68 刚证明过"装上调度不等于它在跑"，所以要在加之前先有一次授权 + 一次**当场实测触发**，
  而不是这次顺手塞进去。与 task #44 一起排队等授权。
- 脚本只走生产 PG（查询用了 `::int` / `to_char`）。它是运维只读工具、不是被测路径，
  为它做双方言只会多一片没人走的代码 —— 与 ADR-0001 的口径一致。
- `.mjs` 里不能有任何 TS 语法（Node 只对 `.ts` 做类型剥离，内联 `import { type X }` 直接
  SyntaxError）。踩过，脚本头部留了注解，判据模块才是带类型的地方。
