# 公示期分布的桶标签重叠，且「少掉的那几条」不给数字

## 审计结论（2026-09-21）

| 检查项 | 结论 |
| --- | --- |
| **公示期分布的分桶口径** | **缺陷**（两处，见下） |
| robots.txt 与 sitemap 的一致性 | 无缺陷 —— robots 只挡 `/admin`、`/go/`、`/api/`，与 sitemap 的 180 条（首页 / 统计页 / 178 条目页）零交集；`Sitemap:` 用绝对地址；`/search`、`/unsubscribe` 等薄页/事务页仍按 issue #38 的决定「可爬 + noindex」（不 Disallow，否则爬虫读不到 noindex） |
| 首页 `ItemList` / `CollectionPage` | 未做 —— 属增强（issue #39 已记为独立议题），不是缺陷 |
| 统计页小计 / 总计的区间钻取 | 未做 —— 需要 `from`/`to` 区间口径（issue #45 已记为后续） |

## 缺陷 1：桶标签与桶边界不一致，30 天落在两个桶里

`getPeriodLengthDistribution` 的边界是 `≤7 / 8-15 / 16-30 / **> 30**`，
而页面标签写的是「**30 天以上**」—— 中文里「30 天以上」含 30，与上一桶
「16-30 天」在 30 这个数上**重叠**：读者无法判断一个公示期恰好 30 天的条目
被算进了哪一桶（实际在 `b16_30`）。

## 缺陷 2：差额只给规则、不给数字

页头写着「收录公示 **178** 条」，而四个分布桶之和是 **176**；说明里只有一句
「缺失发布或截止日期的条目不参与统计」——**没有说差了几条**。读者（或引用这些
数字的人）无法判断这 2 条是被规则排除的、还是漏统计了。线上实测：确实有 2 条
未标注截止日期（都来自国家发展改革委），但页面不说，读者只能猜。

这是本项目反复出现的那一类问题：**数字对不上时，页面必须自己解释差额**
（同族：#19/#31「把截断结果当全量」、#36「两个口径不一致」、#45「格子不能点」）。

## 修复

- 标签改为「**31 天及以上**」（与 `> 30` 精确对应），并在说明里把四档边界写全；
- 差额**动态给出**：`periodExcluded = 收录总数 − 四桶之和`，
  - `> 0` → 「另有 N 条未标注截止日期（或发布日期），不参与统计 —— 四桶之和因此小于收录总数。」；
  - `= 0` → 「全部条目都已标注截止日期，四桶之和等于收录总数。」
  （两种情形都要说，否则读者仍然分不清「没有排除」和「没写」）。

## 验收

- E2E（182，新增 1 + 扩展 1）：`stats.test.mjs` 的分桶用例新增两条断言 ——
  标签必须含「31 天及以上」且**不得再出现**「30 天以上」（与「16-30 天」重叠）；
  差额为 0 时必须出现「四桶之和等于收录总数」；`notice-brief.test.mjs` 用带
  「无截止日期」条目的 fixture 断言非零分支：页面写出的条数必须等于
  「收录总数 − 四桶之和」，且该差额 > 0；
- **红检**：把标签与动态说明一起退回修复前形态 → 两项断言当场变红
  （「最后一个桶的标签应为「31 天及以上」」「页面必须把差额按条数说出来」）；
- 本地全量：单元 140 + E2E 182 全绿，typecheck / lint 干净；
- 线上核验（部署后）：桶标签为「7 天以内（含 7 天）/ 8-15 天 / 16-30 天 / **31 天及以上**」，
  「30 天以上」已不存在；页面写明「另有 **2** 条未标注截止日期（或发布日期），不参与统计」，
  与 `178 − (5+8+105+58)` 一致；**数据库侧独立核对**：178 条中恰好 2 条
  `deadline_at` 为空（均来自 ndrc），桶计数与修复前一致（5/8/105/58）；
  首页 / 统计页 / feed / sitemap 全部 200。
